# 🎉 Happy Birthday — праздники нашего чата

Telegram-бот и Mini App для дней рождения в группах. Без спама: в группе размещается одна постоянная панель, а в дни рождения — персональные поздравления с необязательным закреплением. Новогодние желания и необязательные адреса ПВЗ Wildberries/Ozon уже доступны в Mini App; «Тайного Санты» не будет.

## Этап 1
- Mini App для мобильного Telegram: сохранение дня/месяца, необязательного года, приватности.
- Календарь и ближайшие дни рождения.
- Автоматическое поздравление в группе по её часовому поясу, с персональным упоминанием.
- Закрепление поздравления и снятие закрепления на следующий день, только у сообщения бота.
- Настройки для администраторов (время, часовой пояс, закрепление).
- Проверка подлинности Telegram Mini App initData и членства в группе.

## Запуск

1. Создайте бота в @BotFather и скопируйте токен.
2. Подготовьте HTTPS-адрес Mini App (домен и reverse proxy на порт 3000).
3. В @BotFather настройте **Main Mini App** с HTTPS-адресом `https://ваш-домен/`. Без этого ссылки из групп `https://t.me/имябота?startapp=c-100...` не будут открывать приложение.
4. Скопируйте `.env.example` в `.env`, заполните `BOT_TOKEN` и `BASE_URL`.
5. Запустите: `docker compose up -d --build` (или `pip install -r requirements.txt && PORT=3000 python -m app.main`).
6. Добавьте бота в группу администратором, разрешите **закреплять сообщения**. В группе администратор первый раз пишет `/holidays` — появляется постоянная панель с кнопками Mini App. Затем **любой участник** может написать `/holidays` повторно — бот покажет новое временное меню.
7. Для проверки: `GET /health`; откройте приложение **в Telegram**, не обычным браузером.

Хранение: файл SQLite в `./data` (в Docker volume). Не запускайте одновременно несколько копий приложения с одним токеном и БД. Регулярно копируйте `data/`.

## Устройство

`app/main.py` — FastAPI + Telegram polling + планировщик в одном процессе; `app/bot.py` — команды и кнопки; `app/api.py` — защищённый API Mini App; `app/db.py` — хранилище; `app/scheduler.py` — отправка и закрепление; `app/wishes.py` — списки подарков и приватные ПВЗ; `app/static/` — адаптивный интерфейс.

## Приватность

Год рождения необязателен. Публичное поздравление и отображение в календаре настраиваются участником. API проверяет Telegram initData, его срок и принадлежность к конкретной группе. Ссылочный `startapp` **не является авторизацией**. Дату можно удалить в профиле. Новогодние адреса ПВЗ опциональны и доступны только владельцу либо участнику, который забронировал конкретный подарок.

## Этап 2 — Новогодние желания (реализовано)

- В Mini App есть вкладки **«Мои желания»** и **«Желания друзей»**.
- Участник может создать до 12 активных желаний, добавить название, описание, примерную стоимость, ссылку на Wildberries/Ozon и при желании прямую HTTPS-ссылку на изображение подарка.
- Владелец может изменить, удалить или отметить желание как исполненное.
- Необязательные адреса **пунктов выдачи**, отдельно Wildberries и Ozon, сохраняются в базе. Их нет в общей выдаче или в сообщениях чата.
- Участник может нажать **«Хочу подарить»**, чтобы приватно забронировать подарок. Это не оплата и не заказ. Другим видно, что подарок уже выбран; **владелец не видит бронь**, чтобы сюрприз сохранился.
- Только забронировавший подарок участник видит адреса ПВЗ получателя; доступ проверяется на сервере. При отмене брони доступ исчезает. По одному желанию — не более одной активной брони.
- Для удобства дарителя предусмотрены отдельные кнопки копирования адреса и перехода на страницу товара.
- Списки желаний не публикуются автоматически в группе. **«Тайного Санту» нет.**
- База расширяется дополнительными таблицами при старте, действующие дни рождения не удаляются. Сделайте резервную копию данных перед обновлением сервера.

**Важно:** заказать на ПВЗ другого человека бывает недостаточно для получения: маркетплейс может потребовать QR/код или передачу заказа. Не вводите коды получения в чат/приложение. Оплату и оформление заказа бот не выполняет.

**Как проверить:** обновите деплой на BotHost, откройте Mini App из чат-панели → **🎁 Желания**. Добавьте желание и необязательный адрес ПВЗ, проверьте из второго Telegram-аккаунта в той же группе: чужой адрес не должен отображаться до бронирования. Затем забронируйте, проверьте адрес и отмените бронь.

**Повторное меню:** команда `/holidays` доступна любому участнику и в любой момент. Исходная панель остаётся на месте (в том числе закреплённая), а временные сообщения-меню удаляются через 15 минут или при следующем вызове.

## Следующий этап

Генерация индивидуальных открыток к дням рождения, более удобное добавление фотографий подарков и дополнительные настройки оформления. Сохраняем принцип: минимум сообщений в чате.

## Развёртывание на BotHost (Bothost)

Проект адаптирован под BotHost: сервис использует стандартную точку входа `python -m app.main`, слушает `0.0.0.0`, читает порт из `PORT` (обычно `3000`) и автоматически строит HTTPS-адрес Mini App из переменной `DOMAIN`. `BASE_URL` можно передать вручную, тогда он имеет приоритет.

1. В BotHost выберите GitHub-репозиторий `Kataev95/Happy-birthday-`, ветку `main`. После обновлений GitHub **пересоберите и перезапустите бота**.
2. Во вкладке **Домен** установите `bot-1794821354-7486-pablo.bothost.tech`, порт **3000**; сохраните. Если используется другой адрес, укажите его.
3. В переменных окружения проверьте `BOT_TOKEN` (хранить только в панели хостинга). По желанию явно добавьте `BASE_URL=https://bot-1794821354-7486-pablo.bothost.tech`, если `DOMAIN` не передаётся.
4. Для проверки откройте `https://bot-1794821354-7486-pablo.bothost.tech/health`. Должен вернуться JSON `{"ok":true,"service":"happy-birthday"}`. Главная `/` отдаёт Mini App.
5. В Telegram BotFather → Main App вставьте **полный URL** `https://bot-1794821354-7486-pablo.bothost.tech/`. Без `https://` BotFather выдаёт «URL is invalid».
6. В BotHost проверяйте **логи работы**, не только успешную сборку. При `404` без запросов к Python проверьте, что прокси домена подключён; BotHost может потребовать обновить маршрут после деплоя.

База данных: `/app/data/holidays.sqlite3` при рабочей папке `/app`. Храните `/app/data` в постоянном томе BotHost; не записывайте БД в корень временного контейнера.

**Важно:** URL в BotFather заработает только после исправного запуска HTTP-сервера по HTTPS. 404 от прокси не всегда означает проблему Mini App.


## Быстрое добавление бота в Telegram-группу

В личном диалоге с ботом команда `/start` показывает кнопку
**«➕ Добавить в группу»**, ведущую на
`https://t.me/drmetr_bot?startgroup&admin=pin_messages`.
Telegram откроет выбор групп и предложит выдать право закреплять сообщения;
другие административные права не запрашиваются. Пользователь должен иметь
право назначать администраторов в выбранной группе.

В BotFather у бота должен быть включён параметр **Allow Groups**.
После добавления администратор пишет `/holidays` и создаёт постоянную панель.
В дальнейшем `/holidays` доступна всем участникам: бот присылает новое временное меню с кнопками и автоматически удаляет его через 15 минут, либо заменяет при следующем вызове. Постоянную панель бот не удаляет.


## Кнопка в поздравлении

Каждое **автоматическое поздравление с днём рождения**, в том числе закреплённое
ботом, содержит кнопку **«🎂 Добавить свой ДР»**. Она открывает раздел
«Мой день рождения» в Mini App **конкретно того чата**, в котором отправлено
поздравление. Бот использует ссылку с параметром `startapp=c<chat_id>_b` и
проверяет членство в группе на сервере. Кнопка — часть того же поздравления:
дополнительные сообщения в группу не отправляются.

Изменение применяется к новым поздравлениям после обновления BotHost.
Уже отправленные сообщения не редактируются.


## /holidays в любое время

Команда `/holidays` **не одноразовая**. Первый вызов администратора создаёт постоянную панель для чата. Каждый последующий вызов (включая от обычного участника) показывает свежие кнопки «Мой день рождения», «Календарь», «Новогодние желания». Одновременно в группе хранится не более одного временного меню; временное меню удаляется через 15 минут или при следующем вызове. Исходное закреплённое сообщение и поздравления не затрагиваются. Это хранится в отдельной таблице SQLite `quick_menus` и сохраняется при перезапуске, если `data/` смонтирована постоянно. Повторный `/holidays` не удаляет ничьи дни рождения или списки желаний.


## 💝 Сборы настоящих ирисок в Telegram-чате (без Mini App)

Функция сборов работает **в самой группе**. Каждый участник может создать сбор на подарок,
свадьбу, день рождения или общий призовой фонд. Праздники и желания продолжают работать
через Mini App, как раньше.

Подключение:
1. Получите **Iris Connect API token для этого Telegram-бота** у Ириса. В BotHost добавьте
   секретную переменную среды IRIS_CONNECT_TOKEN (только секретная часть, без ID бота;
   приложение само формирует ID и токен в запросе). Не публикуйте ключ в GitHub.
2. Разверните обновление и перезапустите процесс. Новые таблицы SQLite добавляются автоматически,
   старые дни рождения и желания сохраняются. До обновления сохраните копию базы data/.
3. В группе создайте сбор: /collect На свадьбу | 5000. Бот покажет карточку
   с прогрессом и кнопками **1, 5, 10, 50, 100 и «Своя сумма»**.
4. Участник нажимает на сумму, Telegram открывает **официальный Ирис**, где перевод
   необходимо **подтвердить**. Бот опрашивает Iris Connect API примерно раз в 45 секунд
   и обновляет исходную карточку **только по полученным операциям**.

Команды в чате:
- /collect Название | 5000 — создать сбор. Для защиты от спама не больше двух открытых сборов
  на человека, трёх новых за 24 часа и пятнадцати открытых на группу.
- /collections — список открытых сборов.
- /collect_info ID — показать карточку сбора и кнопки оплаты.
- /collect_close ID — закрыть свой сбор (администратор тоже может).
- /collect_review ID — **только администратор группы**: показать неподписанные переводы из истории Ириса, выбрать операцию и отдельно подтвердить её привязку к этому сбору. Ничего не зачисляется без подтверждения администратора; операции проверяются на дубликаты, фиксируются в журнале. Применять только после сверки с оригинальной историей и отправителем.\n- /collect_pay ID — **только администратор группы**: перечислить собранные ириски организатору
  через Iris API. Доступно через 24 часа после закрытия на время сверки поступлений.
  Выплата выполняется **не более одного раза**. Если ответ Ириса неясен/истекло время ожидания,
  сбор получает статус «Проверка выплаты» — автоматически повторять операцию **нельзя**.

**Как устроены деньги.** Сборы — это разные строки в БД, но поступления физически
идут в **общий мешок подключённого бота**. Он обязан иметь достаточно ирисок для выплат.
В текущей версии комиссия платформы **0%** (комиссии самого Ириса могут отличаться).
Указанный организатор должен иметь возможность получать переводы. Создавать сборы разрешено
обычным участникам, однако запуск выплаты вручную доверен администратору группы.
Используйте эту функцию только в чатах, где участники доверяют управляющему мешком.

**Учет.** Пожертвования распознаются по уникальному комментарию в Iris deep link и
входящим событиям sweets_log / receive API версии v0.5.
У каждой операции есть уникальный ID, повторное событие не увеличивает сумму. Переводы без
корректной привязки остаются в журнале iris_collection_events со статусом unmatched,
не приписываются случайному сбору. После закрытия старые ссылки Ириса **не отзываются**:
поздние переводы после начала выплаты потребуют ручной сверки/возврата.
**Проверить перед использованием реальных сумм:** перевод 1 🍬, запись события, обновление
карточки, затем закрытие и тестовый вывод; формат комментариев и доступ Iris API могут
меняться независимо от нашего кода.

Бот не пытается списывать средства пользователя: каждый перевод подтверждается самим
участником в официальном Ирисе. Логи внешних транзакций (включая несопоставленные)
хранятся в SQLite. Блокировка или удаление бота/БД не заменяет обязательства перед
отправителями и организаторами.

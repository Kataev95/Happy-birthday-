# 🎉 Happy Birthday — праздники нашего чата

Telegram-бот и Mini App для дней рождения в группах. Без спама: в группе размещается одна постоянная панель, а в дни рождения — персональные поздравления с необязательным закреплением. Новогодние желания и необязательные адреса ПВЗ Wildberries/Ozon уже доступны в Mini App; «Тайного Санты» не будет.

## Этап 1
- Mini App для мобильного Telegram: сохранение дня/месяца, необязательного года, приватности.
- Календарь и ближайшие дни рождения.
- Автоматическое поздравление в группе по её часовому поясу, с персональным упоминанием.
- Закрепление поздравления и снятие закрепления на следующий день, только у сообщения бота.
- Настройки для администраторов (время, часовой пояс, закрепление).
- Проверка подлинности Telegram Mini App initData и членства в группе.

## Запуск

1. Создайте бота в @BotFather и скопируйте токен.
2. Подготовьте HTTPS-адрес Mini App (домен и reverse proxy на порт 3000).
3. В @BotFather настройте **Main Mini App** с HTTPS-адресом `https://ваш-домен/`. Без этого ссылки из групп `https://t.me/имябота?startapp=c-100...` не будут открывать приложение.
4. Скопируйте `.env.example` в `.env`, заполните `BOT_TOKEN` и `BASE_URL`.
5. Запустите: `docker compose up -d --build` (или `pip install -r requirements.txt && PORT=3000 python -m app.main`).
6. Добавьте бота в группу администратором, разрешите **закреплять сообщения**. В группе администратор первый раз пишет `/holidays` — появляется постоянная панель с кнопками Mini App. Затем **любой участник** может написать `/holidays` повторно — бот покажет новое временное меню.
7. Для проверки: `GET /health`; откройте приложение **в Telegram**, не обычным браузером.

Хранение: файл SQLite в `./data` (в Docker volume). Не запускайте одновременно несколько копий приложения с одним токеном и БД. Регулярно копируйте `data/`.

## Устройство

`app/main.py` — FastAPI + Telegram polling + планировщик в одном процессе; `app/bot.py` — команды и кнопки; `app/api.py` — защищённый API Mini App; `app/db.py` — хранилище; `app/scheduler.py` — отправка и закрепление; `app/wishes.py` — списки подарков и приватные ПВЗ; `app/static/` — адаптивный интерфейс.

## Приватность

Год рождения необязателен. Публичное поздравление и отображение в календаре настраиваются участником. API проверяет Telegram initData, его срок и принадлежность к конкретной группе. Ссылочный `startapp` **не является авторизацией**. Дату можно удалить в профиле. Новогодние адреса ПВЗ опциональны и доступны только владельцу либо участнику, который забронировал конкретный подарок.

## Этап 2 — Новогодние желания (реализовано)

- В Mini App есть вкладки **«Мои желания»** и **«Желания друзей»**.
- Участник может создать до 12 активных желаний, добавить название, описание, примерную стоимость, ссылку на Wildberries/Ozon и при желании прямую HTTPS-ссылку на изображение подарка.
- Владелец может изменить, удалить или отметить желание как исполненное.
- Необязательные адреса **пунктов выдачи**, отдельно Wildberries и Ozon, сохраняются в базе. Их нет в общей выдаче или в сообщениях чата.
- Участник может нажать **«Хочу подарить»**, чтобы приватно забронировать подарок. Это не оплата и не заказ. Другим видно, что подарок уже выбран; **владелец не видит бронь**, чтобы сюрприз сохранился.
- Только забронировавший подарок участник видит адреса ПВЗ получателя; доступ проверяется на сервере. При отмене брони доступ исчезает. По одному желанию — не более одной активной брони.
- Для удобства дарителя предусмотрены отдельные кнопки копирования адреса и перехода на страницу товара.
- Списки желаний не публикуются автоматически в группе. **«Тайного Санту» нет.**
- База расширяется дополнительными таблицами при старте, действующие дни рождения не удаляются. Сделайте резервную копию данных перед обновлением сервера.

**Важно:** заказать на ПВЗ другого человека бывает недостаточно для получения: маркетплейс может потребовать QR/код или передачу заказа. Не вводите коды получения в чат/приложение. Оплату и оформление заказа бот не выполняет.

**Как проверить:** обновите деплой на BotHost, откройте Mini App из чат-панели → **🎁 Желания**. Добавьте желание и необязательный адрес ПВЗ, проверьте из второго Telegram-аккаунта в той же группе: чужой адрес не должен отображаться до бронирования. Затем забронируйте, проверьте адрес и отмените бронь.

**Повторное меню:** команда `/holidays` доступна любому участнику и в любой момент. Исходная панель остаётся на месте (в том числе закреплённая), а временные сообщения-меню удаляются через 10 минут или при следующем вызове.

## Следующий этап

Генерация индивидуальных открыток к дням рождения, более удобное добавление фотографий подарков и дополнительные настройки оформления. Сохраняем принцип: минимум сообщений в чате.

## Быстрое добавление бота в Telegram-группу

В личном диалоге с ботом команда `/start` показывает кнопку
**«➕ Добавить в группу»**, ведущую на
`https://t.me/drmetr_bot?startgroup&admin=pin_messages`.
Telegram откроет выбор групп и предложит выдать право закреплять сообщения;
другие административные права не запрашиваются. Пользователь должен иметь
право назначать администраторов в выбранной группе.

В BotFather у бота должен быть включён параметр **Allow Groups**.
После добавления администратор пишет `/holidays` и создаёт постоянную панель.
В дальнейшем `/holidays` доступна всем участникам: бот присылает новое временное меню с кнопками и автоматически удаляет его через 10 минут, либо заменяет при следующем вызове. Постоянную панель бот не удаляет.


## Кнопка в поздравлении

Каждое **автоматическое поздравление с днём рождения**, в том числе закреплённое
ботом, содержит кнопку **«🎂 Добавить свой ДР»**. Она открывает раздел
«Мой день рождения» в Mini App **конкретно того чата**, в котором отправлено
поздравление. Бот использует ссылку с параметром `startapp=c<chat_id>_b` и
проверяет членство в группе на сервере. Кнопка — часть того же поздравления:
дополнительные сообщения в группу не отправляются.

Изменение применяется к новым поздравлениям после обновления BotHost.
Уже отправленные сообщения не редактируются.


## /holidays в любое время

Команда `/holidays` **не одноразовая**. Первый вызов администратора создаёт постоянную панель для чата. Каждый последующий вызов (включая от обычного участника) показывает свежие кнопки «Мой день рождения», «Календарь», «Новогодние желания». Одновременно в группе хранится не более одного временного меню; временное меню удаляется через 10 минут или при следующем вызове. Исходное закреплённое сообщение и поздравления не затрагиваются. Это хранится в отдельной таблице SQLite `quick_menus` и сохраняется при перезапуске, если `data/` смонтирована постоянно. Повторный `/holidays` не удаляет ничьи дни рождения или списки желаний.



## 💝 Автоматический сбор настоящих ирисок прямо в Telegram-чате

**Без Mini App и без ручного зачисления.** Дни рождения, календарь и списки
желаний продолжают работать как прежде.

### Участник чата

1. Напиши `/collect На свадьбу | 5000` — в чате появится карточка с целью и
   кнопками 1/5/10/50/100 🍬 и «Своя сумма».
2. Желающий поддержать нажимает сумму **в карточке**. Это callback-кнопка, по
   которой бот уже знает точный Telegram ID плательщика и создаёт
   персональную **ожидаемую операцию** (10 минут).
3. В том же чате появляется его персональная кнопка **«Перевести через Ирис»**
   с официальным адресом Iris. Он подтверждает перевод в Ирисе.
4. Раз в ~45 секунд бот запрашивает **подтверждённые входящие операции** через
   Iris Connect API. Если ID отправителя (`peer_id`), время и сумма совпали
   с единственной активной заявкой, перевод автоматически засчитывается.
   При наличии `details.total` / `details.fee` сверяется реальная комиссия,
   а не предполагается фиксированная. Если данные отсутствуют — используется
   ограниченная проверка с точным ID отправителя и временем.
   Карточка редактируется; отдельный платёжный пост удаляется.
5. Под прогрессом сразу появляются **имена участников и суммы их подтверждённых
   взносов (по факту полученных ирисок)**. Кнопка «👥 Все участники»
   открывает список с перелистыванием прямо в чате.
6. При достижении цели бот закрывает сбор автоматически, скрывает кнопки
   платежей и выводит «🏆 ЦЕЛЬ ДОСТИГНУТА!». Уже собранное сохраняется.

**ВНИМАНИЕ:** Iris может удалить комментарий `give_bot...`, что и происходило
на реальных тестах. Поэтому новая схема больше не требует комментарий для
сопоставления. Однако это сопоставление по ID + времени + сумме, **не
криптографическое подтверждение назначения платежа**. Совпавший сторонний
перевод в узком временном окне — остаточный риск. Если в истории
нет `peer_id`, операция выходит за временное окно, сумма не совпадает,
или бот был недоступен так долго, что история уже вытеснена — бот
**не будет угадывать**, кому принадлежит поступление.

Сумма, зачисляемая на сбор, равна **реально полученной**. Если история Ириса
содержит `details.total`, бот сверяет её с запрошенной суммой; при наличии
`details.fee` дополнительно проверяет согласованность с фактически полученным.
Без `details` применяется ограниченный резервный алгоритм, только при
совпадении отправителя и времени. Если API вернул противоречивые данные,
операция не зачисляется. Переводы должны выполняться только по собственной
персональной кнопке, а не по пересланной чужой ссылке.
Надёжность этого режима зависит от того, возвращает ли Iris в истории
фактический Telegram ID плательщика: без него автоматическое распределение
по сбору **невозможно выполнить достоверно**.

### Команды

- `/collect Название | 5000` — создать сбор (не более двух открытых
  на человека, трёх новых в сутки и пятнадцати открытых на чат).
- `/collections` — список сборов.
- `/collect_info ID` — карточка и кнопки.
- `/collect_donors ID` — имена участников, итоговые суммы и число взносов;
  доступно любому участнику того же чата.
- `/collect_close ID` — досрочно закрыть свой сбор.
- `/collect_status ID` — диагностировать синхронизацию API (администраторам).
- `/collect_pay ID` — выплата организатору из мешка через Iris Connect,
  только администратором, после закрытия и 24 часов на проверку. Этот
  **отдельный этап выплаты** пока не автоматизирован: нельзя без проверки
  запускать денежный перевод при риске неопределённого ответа API.

Ручная команда `/collect_review` и кнопки ручного зачисления **убраны**.
Исторические взносы, зачисленные через них до обновления, в SQLite
сохраняются и не начисляются повторно. Для старых взносов, по которым
имя пользователя ранее не сохранялось, бот показывает «Участник» вместо
того, чтобы выдумывать имя. Подтверждённые поступления, у которых нет
однозначного назначения, НЕ попадают в чужие сборы.

### Конфигурация

В BotHost установить секрет `IRIS_CONNECT_TOKEN` (безопаснее в панели
настроек, не в GitHub) и обновить бота из ветки main. Новый код добавляет
таблицу `iris_payment_intents` и добавляет сохранение имён доноров;
существующие даты, подарки и сборы не удаляются. Бот **автоматически
обновляет ранее опубликованные карточки** при перезапуске. Это необходимо:
старые кнопки прямого перехода в Iris обходят персональную заявку и
не могут быть автоматически сопоставлены. Обязательно сохраните резервную
копию папки `data/`.

Поступления идут в **общий мешок бота**, а не непосредственно
организатору. Комиссия *платформы* в текущей версии 0%, комиссия Ириса
может быть иной. По условиям Iris Connect важно сохранять журнал
средств и не допускать двойных зачислений. Операции учитываются
по уникальному внешнему ID в SQLite; повторные ответы API и перезапуски
не должны изменять итог второй раз.

### Проверка

После обновления отправь новый сбор `/collect Проверка | 2`.
Нажми «🍬 1» **в карточке** и убедись, что появляется **НОВОЕ персональное
сообщение в группе**, затем подтверди перевод в Ирисе. В течение следующих
успешных циклов синхронизации сумма должна обновиться без
`/collect_review`. Если пользователь платил в пределах первоначального
10-минутного окна, а обработчик тогда не распознал операцию,
версия v2 может восстановить платёж по старой, уже истёкшей заявке
за последние 72 часа — только если совпадение достоверно.
После зачисления рядом с суммой появится Telegram-имя и размер взноса.
Для технической проверки (без токенов или личных ID) администратор пишет
`/collect_status ID`, получает количество записей с `peer_id`, доступность
`details` и число потенциальных совпадений. Никогда не отправляйте
токены или полные сырые ответы API в чат. Если нет подтверждённого
`peer_id`, бот не имеет права угадывать владельца перевода.

### Выплата и предупреждение о задержках

На карточке сбора и под персональной кнопкой отображается предупреждение, что
Iris Connect синхронизируется с задержкой (опрос примерно раз в 45 секунд,
при проблемах API дольше). Участники не должны отправлять ириски повторно,
пока первый перевод проверяется.

Собранные ириски физически находятся в **мешке подключённого бота**. Получатель
выплаты — **тот участник, который создал сбор**, то есть `owner_id`, даже
если выплату запускает другой администратор чата. После закрытия сбора
администратор этого же чата может через **24 часа** запустить
`/collect_pay НОМЕР_СБОРА` (например, `/collect_pay 3`). Выплата доступна
только для `closed` и только один раз. Возможны комиссии Ириса, поэтому в
мешке должно быть достаточно средств. Если API отвечает неясно, сбор
переходит в `review`; повторять команду до сверки истории **нельзя**.

Iris API может вернуть ID исходящего перевода в двух форматах:
`{"result": 123}` или `{"result": {"result": 123}}`. Оба распознаются, чтобы
успешная выплата не считалась ошибкой из-за вложенной структуры.
